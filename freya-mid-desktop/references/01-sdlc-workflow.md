# SDLC Workflow & Interview Scripts

本文档定义了 AI 代理在 **Phase 1: 需求澄清** 阶段必须遵循的沟通话术和提问模板。你必须扮演资深产品经理 (PM)，通过结构化的提问，消除需求中的所有歧义。

## 1. 需求澄清三步走 (Phase 1 Rounds)

### 🔴 Round 1: 核心价值探测 (Core Concept)
**目标**: 锁定软件的“灵魂”。
**你的行动**: 如果用户只说“我要做个记事本”，你必须追问：
*   “请问这个工具的最核心能力是什么？”
*   “它最主要的输入方式是文本粘贴、文件拖拽，还是本地目录扫描？”
*   “期望的输出形态是什么样的（弹窗提示、列表展示、导出文件）？”

### 🟡 Round 2: 业务逻辑排雷 (Business Logic)
**目标**: 像测试工程师一样思考边界情况。
**你的行动**: 针对第一轮确认的核心功能，列出 3-5 个潜在的异常或细节分支，逐条确认：
*   *示例 (JSON格式化)*: “1. 遇到非法 JSON 时，是弹窗报错还是尝试自动修复？2. 格式化结果是否需要一键复制？3. 是否需要多标签页处理？”
*   *示例 (图片压缩)*: “1. 同名文件覆盖还是重命名？2. 是否需要保留 EXIF 信息？3. 压缩进度如何展示（列表独立进度条还是全局总进度）？”

### 🟢 Round 3: 系统与工程边界敲定 (Engineering Bounds)
**目标**: 决定底层技术选型和依赖规模。
**你的行动**: 在业务逻辑清晰后，抛出以下标准化问题（可提供默认推荐）：
1. **系统权限 (I/O)**: 是否需要读写本地磁盘（哪里的目录）？是否需要网络请求？
2. **后台与系统托盘 (Daemon)**: 关闭主窗口时，是直接杀进程退出，还是缩小到右下角托盘 (System Tray) 继续运行？是否需要开机自启？
3. **配置持久化 (Settings)**: 除了深浅色主题，还有哪些用户偏好（如默认保存路径、API Key）需要永久保存在本地 `~/.config/`？
4. **国际化 (i18n)**: 目前仅支持单语言，还是需要预留多语言切换机制（如引入 `fluent-templates`）？

---

## 2. 需求文档标准模板 (PRD Template)

在完成三轮对话并得到用户确认后，你必须生成严格格式的 `docs/requirements.md`。

```markdown
# 产品需求规格说明书 (PRD)

## 1. 产品定位 (Product Vision)
- **名称**: [App Name]
- **核心功能**: [一句话描述，如：本地无损图片压缩工具]
- **目标用户**: [如：需要批量处理素材的开发者/设计师]

## 2. 核心交互场景 (User Stories)
- [ ] 用户可以将单张或多张图片拖入 Main Stage (Drop Zone)。
- [ ] 侧边栏 (Activity Bar) 或主视图显示当前处理队列的状态。
- [ ] [其他核心交互...]

## 3. 业务规则与异常流 (Business Rules & Edge Cases)
- **输入异常**: [如：拖入非图片格式文件时的表现]
- **处理异常**: [如：网络断开、权限不足时的表现]
- **输出约束**: [如：自动在原文件名后追加 _compressed]

## 4. 系统级能力要求 (System Capabilities)
- [ ] **文件系统**: [读写路径权限要求]
- [ ] **网络访问**: [是/否，具体用途]
- [ ] **剪贴板**: [是/否，具体用途]
- [ ] **后台常驻**: [是/否，是否需要托盘图标]

## 5. 持久化设置项 (Settings State)
1. `theme`: 深色/浅色/系统 (默认: 系统)。
2. `[其他配置项]`: [说明及默认值]。

## 6. 国际化 (i18n)
- **当前支持**: [如：简体中文]
- **预留多语言**: [是/否]
```
