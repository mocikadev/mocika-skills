# AI 入口文件推荐结构与模板

## 推荐章节结构

默认生成 `AGENTS.md`。如果项目已明确使用 `CLAUDE.md` 或 `GEMINI.md`，沿用现有入口文件，不强行迁移。

推荐包含以下核心章节，按顺序组织；确无内容的章节可省略，但不得为了凑模板编造泛化约束：

```
# 项目名
> 导航说明一句话

## 项目概览
## 技术栈
## AI 执行协议摘要
## 开发/协作约束       ← 只写项目特有高优先级规则
## 提交前检查清单
## 关键约束
## 常用命令
## 文档导航
## Skills 导航
```

## AI 执行协议摘要

- 需求不清时，先补齐 `docs/requirements/project-spec.md`，再进入设计或实现
- 普通/复杂变更遵循 `spec → 设计/计划 → 实现 → 验证 → 汇报`
- 复杂变更实现前，先确认变更级执行契约：目标、行为、约束、任务批次、测试义务
- Bug 修复遵循 `复现/确认 → 根因定位 → 回归验证 → 修复 → 验证`
- 完整规则：`docs/ai/execution-protocol.md`

## 高价值内容（必须保留在 AGENTS.md，不得下沉）

- **跨文件同步约束**：修改 X 必须同步修改 Y（AI 最容易遗漏的）
- **有序提交前检查清单**：带顺序和踩坑提示的 bash 命令块
- **AI 执行协议摘要**：spec/计划/验证等项目级执行门槛的入口链接
- **特殊路径约定**：共享锁文件、中央目录、配置文件位置
- **当前项目状态**：阶段标记，让 AI 知道现在处于开发的哪个阶段
- **不可从代码推断的约束**：最低运行时/语言版本要求、二进制命名规范、平台兼容要求
- **项目特有高风险操作提示**：全局规则未覆盖、且会影响本项目的破坏性操作

## 验收检查清单

- [ ] 入口文件优先 ≤ 120 行；大型仓库可放宽，但明显细则必须下沉
- [ ] 章节按推荐顺序组织，无空洞模板内容
- [ ] AI 执行协议摘要存在，并链接到 `docs/ai/execution-protocol.md`
- [ ] 项目 spec 或需求入口存在；新项目不得缺少验收标准
- [ ] 开发/协作约束章节只写项目特有规则，且带 ⚠️ 高优先级标记
- [ ] 项目概览包含：名称、一句话说明、当前状态
- [ ] 提交前检查清单是有序 bash 代码块（不是散文描述）
- [ ] 关键约束包含跨文件同步要求（如有）
- [ ] 没有重复全局 AGENTS.md 中已有的通用规则
- [ ] 文档导航路径真实存在或本次同步新建
- [ ] docs/ 骨架按项目需要创建；未创建的候选目录不得写成已存在
