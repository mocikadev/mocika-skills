# project-ai-system

为项目生成并维护项目级 AI 工作系统的 AI Agent 技能包。

> 原 `agents-map` 已升级并改名为 `project-ai-system`。

核心理念：**先把要做什么和怎么验收说清楚，再让 AI 执行。** 入口文件是地图，不是百科全书；详细 spec、执行协议和规范放 `docs/` 或 project skill，AI 按需查阅。

## 解决什么问题

- 新项目只有想法、需求不清晰 → **启动模式**
- 已有清晰需求，需要给 AI 建立上下文 → **生成模式**
- `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 越写越长，AI 加载慢、容易忽略关键约束 → **修订模式**
- 不确定现有 AI 入口文件是否规范 → **审计模式**
- 项目文档散落在根目录或结构混乱，AI 找不到 → **整理模式**

---

## 五种模式详解

### 启动模式

适用于新项目、需求模糊或只有一句想法的场景。

**输入**：项目想法、目标、已有约束或用户口头描述

**输出**：
- `docs/requirements/project-spec.md` 草稿：目标、范围、非目标、用户场景、验收标准
- `docs/ai/execution-protocol.md` 草稿：AI 接任务、设计、实现、验证和汇报的项目规则
- 复杂变更的执行契约建议：`docs/ai/changes/<change-name>/execution-contract.md`
- 后续生成入口文件和 docs 骨架所需的基础信息

### 生成模式

适用于已有清晰 spec，或从零开始建立 AI 上下文。

**输入**：项目目录、已有 spec 或已澄清需求

**输出**：
- AI 入口文件完整草稿（默认 `AGENTS.md`；若项目已有 `CLAUDE.md`/`GEMINI.md` 则沿用）
- `docs/` 目录骨架建议（按项目需要创建，不强制全量空目录）
- AI 执行协议摘要和 `docs/ai/execution-protocol.md` 链接
- project skill 建议清单（名称 + 说明 + 存放路径）

### 修订模式

适用于现有 AI 入口文件过长、内容冗余或结构混乱。

**输入**：现有 `AGENTS.md`、`CLAUDE.md` 或 `GEMINI.md`

**输出**：
- 修订后的完整入口文件草稿（不只给 diff）
- 迁移建议：哪些内容应下沉到 `docs/` 的哪个目录
- 哪些流程适合拆成独立 project skill

### 审计模式

适用于想检查 AI 入口文件质量但不想直接修改。

**输入**：现有 AI 入口文件

**输出**：
- 问题清单（类型 / 位置 / 建议操作）
- 按 P0-P3 分级的审计报告
- 优先修复顺序：缺少 spec/验收标准 > 缺少执行协议/执行契约 > 缺少验证和收口同步 > 过长 > 重复全局规则 > 缺少关键约束 > 缺少导航

### 整理模式

适用于项目文档散落在根目录或 `docs/` 结构混乱。

**输入**：项目所有文档文件（自动扫描根目录、`docs/`、`notes/` 等）

**输出**：
- 迁移清单（当前路径 → 建议路径 + 是否需要拆分）
- 不自动执行移动，由用户确认后操作

## 生成的入口文件结构

推荐包含以下章节。按顺序组织，允许省略确无内容的章节，避免为了模板完整而填充泛化内容：

```
# 项目名
> 此文件是 AI 代理的项目导航地图

## 项目概览       ← 项目名、一句话说明、当前阶段状态
## 技术栈         ← 语言、框架、关键依赖
## AI 执行协议摘要 ← spec、设计/计划、验证和风险操作的最低门槛
## 开发/协作约束  ← ⚠️ 仅写项目特有高优先级约束
## 提交前检查清单 ← 有序 bash 命令块，含踩坑提示
## 关键约束       ← 跨文件同步要求、特殊路径、AI 无法从代码推断的约束
## 常用命令       ← 启动、构建、测试命令速查
## 文档导航       ← 指向 docs/ 各子目录的索引表
## Skills 导航    ← 项目专属 skill 清单
```

## 生成的 docs/ 骨架

```text
docs/
  requirements/   # 需求文档：功能描述、用户故事、验收条件
  design/         # 技术设计：架构、模块划分、数据流、API 设计
  ui/             # UI/UX 设计：交互稿、组件规范、视觉规范
  development/    # 开发记录：实现细节、技术决策、ADR
  bugfix/         # Bug 修订：修复记录、已知问题、版本变更
  process/        # 流程规范：提交规范、发布流程、分支策略
  style/          # 代码风格：命名约定、注释规范、格式要求
  quality/        # 测试质量：测试策略、覆盖率要求、验收标准
  ops/            # 运维部署：部署流程、环境配置（可按需省略）
  ai/             # AI 代理补充说明、project skill 设计记录（可按需省略）
```

这些目录是候选骨架，不要求小项目一次性全部创建。每个目录按版本/功能/时间拆分文件，不堆在单一文件里。

## 产物示例

- **入口文件草稿**：完整 Markdown 文本，可直接保存为 `AGENTS.md`、`CLAUDE.md` 或 `GEMINI.md`
- **项目 Spec 草稿**：`docs/requirements/project-spec.md`，说明目标、范围、非目标和验收标准
- **AI 执行协议草稿**：`docs/ai/execution-protocol.md`，说明任务分级、需求澄清、执行契约、快速路径、测试/TDD、验证、收口同步和风险操作规则
- **变更执行契约草稿**：`docs/ai/changes/<change-name>/execution-contract.md`，说明复杂变更的目标锁定、已批准行为、任务批次和审查门禁
- **审计报告**：Markdown 表格，按 P0-P3 标注问题、影响、位置、建议和是否阻塞实现
- **docs 骨架建议**：按需创建的目录清单，格式为 `docs/<category>/`
- **迁移清单**：Markdown 表格，包含当前路径、建议路径、原因和是否需要拆分
- **project skill 建议**：技能名称、触发场景、建议路径和为什么不放 docs/入口文件

## 安装

```bash
skm install mocikadev/mocika-skills:project-ai-system --link-to all
```

## 使用

在 AI Agent 会话中加载此 skill，然后描述你的需求：

```
我想做一个新项目，帮我先把需求和 AI 执行规则定清楚 → 启动模式
帮我初始化项目的 AGENTS.md        → 生成模式
我的 AGENTS.md 太长了，帮我重构   → 修订模式
检查一下我的 AGENTS.md 是否规范   → 审计模式
帮我整理项目文档，归类到 docs/    → 整理模式
把 CLAUDE.md 里的细则整理成地图   → 修订模式
```
