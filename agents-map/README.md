# agents-map

为项目生成并维护"地图式" AI 导航体系的 AI Agent 技能包。

核心理念：**AGENTS.md 是地图，不是百科全书。** 详细规范放 `docs/`，AI 按需查阅；AGENTS.md 只保留入口、导航和高优先级约束，始终保持 ≤ 100 行。

## 解决什么问题

- 新项目不知道怎么给 AI 建立上下文 → **生成模式**
- AGENTS.md 越写越长，AI 加载慢、容易忽略关键约束 → **修订模式**
- 不确定现有 AGENTS.md 是否规范 → **审计模式**
- 项目文档散落在根目录或结构混乱，AI 找不到 → **整理模式**

---

## 四种模式详解

### 生成模式

适用于新项目或从零开始建立 AI 上下文。

**输入**：项目目录（自动扫描技术栈、README、CI 配置等）  
**输出**：
- `AGENTS.md` 完整草稿（8 个固定章节，含开发流程约束）
- `docs/` 目录骨架（9 个标准目录，按需选用）
- project skill 建议清单（名称 + 说明 + 存放路径）

### 修订模式

适用于现有 AGENTS.md 过长、内容冗余或结构混乱。

**输入**：现有 `AGENTS.md`  
**输出**：
- 修订后的完整 `AGENTS.md` 草稿（不只给 diff）
- 迁移建议：哪些内容应下沉到 `docs/` 的哪个目录
- 哪些流程适合拆成独立 project skill

### 审计模式

适用于想检查 AGENTS.md 质量但不想直接修改。

**输入**：现有 `AGENTS.md`  
**输出**：
- 问题清单（类型 / 位置 / 建议操作）
- 优先修复顺序：超长 > 重复全局规则 > 缺少关键约束 > 缺少导航

### 整理模式

适用于项目文档散落在根目录或 `docs/` 结构混乱。

**输入**：项目所有文档文件（自动扫描根目录、`docs/`、`notes/` 等）  
**输出**：
- 迁移清单（当前路径 → 建议路径 + 是否需要拆分）
- 不自动执行移动，由用户确认后操作

## 生成的 AGENTS.md 结构

生成的 AGENTS.md 固定包含 8 个章节，顺序不可变：

```
# 项目名
> 此文件是 AI 代理的项目导航地图

## 项目概览       ← 项目名、一句话说明、当前阶段状态
## 技术栈         ← 语言、框架、关键依赖
## 开发流程约束   ← ⚠️ 高优先级：需求→设计→开发→测试→发布，禁止跨阶段
## 提交前检查清单 ← 有序 bash 命令块，含踩坑提示
## 关键约束       ← 跨文件同步要求、特殊路径、AI 无法从代码推断的约束
## 常用命令       ← 启动、构建、测试命令速查
## 文档导航       ← 指向 docs/ 各子目录的索引表
## Skills 导航    ← 项目专属 skill 清单
```

---

## 生成的 docs/ 骨架

```text
docs/
  requirements/   # 需求文档：功能描述、用户故事、验收条件
  design/         # 技术设计：架构、模块划分、数据流、API 设计
  ui/             # UI/UX 设计：交互稿、组件规范、视觉规范
  development/    # 开发记录：实现细节、技术决策、ADR
  bugfix/         # Bug 修订：修复记录、已知问题、版本变更
  process/        # 流程规范：提交规范、发布流程、分支策略
  style/          # 代码风格：命名约定、注释规范、格式要求
  quality/        # 测试质量：测试策略、覆盖率要求、验收标准
  ops/            # 运维部署：部署流程、环境配置（可按需省略）
```

每个目录按版本/功能/时间拆分文件，不堆在单一文件里。

## 安装

```bash
skm install mocikadev/mocika-skills:agents-map --link-to all
```

## 使用

在 AI Agent 会话中加载此 skill，然后描述你的需求：

```
帮我初始化项目的 AGENTS.md        → 生成模式
我的 AGENTS.md 太长了，帮我重构   → 修订模式
检查一下我的 AGENTS.md 是否规范   → 审计模式
帮我整理项目文档，归类到 docs/    → 整理模式
```
